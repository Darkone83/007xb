# 007xb Asset Studio v0.6 — one ROM in, one Xbox archive out

007xb Asset Studio accepts **one user-provided clean GoldenEye 007 NTSC-U rev 0 ROM**
(`.z64`, `.v64`, `.n64`) and creates **only** `data/007xb_assets.dat` for
Xbox deployment. No game assets or ROM are distributed with this tool.

## Folder layout

```
007xb/
  007xb/                            Xbox source (unchanged)
  data/
    007xb_assets.dat                ONLY deployable output, created by the packer
  tools/
    007xb Asset Studio.pyw          GUI (one ROM input)
    Start 007xb.cmd                 Run GUI (uses EXE if built)
    Build Windows EXE.cmd           Build standalone Windows EXE
    007xb_studio_cli.py             Developer CLI
    007xb_assets.py                 Archive writer and developer commands
    xb_studio_pipeline.py           Shared GUI/CLI backend
    007xb_converter_reference.zip   Converter scripts/reference metadata; no ROM
    branding/                       Source logo for packed archive
    docs/                           Tool documentation/tests
    tests/                          Tool regression tests
    .cache/                         Generated temporary conversion files/logs
    dist/                           Built Windows EXE (only after packaging)
```

**All tools, launchers, build commands, and tool-generated intermediate files
stay under `tools/`.** Only the final `.dat` goes to the project's `data/`.
The game reads `D:\data\007xb_assets.dat` beside `default.xbe` (D: is the title
folder on Xbox).

## Using the GUI (Windows)

1. Put this entire `tools/` directory inside your 007xb project folder.
2. Install Python 3.10+ with Tkinter, or use a Windows EXE built from the script.
3. Double-click `tools/Start 007xb.cmd` (or `tools/007xb Asset Studio.pyw`).
4. Choose your clean original **US GoldenEye 007** ROM.
5. Click **Build Archive**.
6. Copy **only** `data/007xb_assets.dat` to Xbox `D:\data\007xb_assets.dat`.

The ROM identity is checked after byte-order normalization using SHA-1
`abe01e4aeb033b6c0836819f549c791b26cfde83`. Unrecognized ROMs are rejected.

## What happens internally

- The ROM is normalized and cached under `tools/.cache/007xb-asset-studio/`.
- The included PC-port converters generate verified model, stage and setup
  sidecars **in that private cache**. No full loose image/audio/model extraction
  is performed.
- A packed wireframe logo is generated in the same private cache.
- An indexed `.dat` archive (6 entries: ROM, 4 sidecars/manifests, logo) is
  built and CRC-verified before atomically replacing the existing final `.dat`.
- Build logs, reports and manifests remain under `tools/.cache/`, **not `data/`**.

Normal builds never delete or overwrite unrelated user files. An old
`data/extracted/` directory from v0.5 will be left alone; **it is not needed
for this working Phase 2 build and should not be copied to Xbox**.

## Developer CLI

```
py -3 tools\007xb_studio_cli.py --rom "C:\Games\GoldenEye (U).z64"
```

Do not use the legacy `extract-upstream` developer command for a normal Xbox
pack. It is diagnostic tooling only; the GUI and CLI use the single-file path.

## Build Windows executable

From the repo, double-click `tools/Build Windows EXE.cmd`.
Requires Python 3 and PyInstaller (`py -3 -m pip install pyinstaller`).
Build products remain in `tools/dist/`; temporary PyInstaller artifacts go to
`tools/.cache/pyinstaller/`. `tools/Start 007xb.cmd` will run that EXE if present.
For a portable distribution, install the EXE into a `tools/` folder. The EXE
still requires only the user's ROM, and writes to the enclosing `data/` folder.

Windows executable creation remains **unverified on Windows**; the source
GUI and CLI are independently testable. Neither archive contains game bytes.

## Changes from v0.5 and manual cleanup

Replace/add the files under `tools/` in the patch ZIP, preserving paths.
After confirming v0.6 launches, you may delete these **old packer-only** files
from the project root (if present):

- `007xb Asset Studio.pyw`
- `Build Windows EXE.cmd`
- `Start 007xb.cmd`
- `tests/test_studio.py` (old v0.5 packer tests only)
- `docs/ROM_ONLY_PACKER_V05_VALIDATION.md` (old packer report only)

The root `README.md` may be your Xbox project README, so **do not delete it**;
update its tool reference to `tools/README.md` if desired. The old root
`branding/` folder may be used by your wider project, so leave it alone until
you determine whether it's exclusively the packer's old copy.

Old `data/` assets, `external/` staging, and `config/` were generated by
older tool versions. Review them and remove only what you no longer use;
v0.6 never deletes them automatically.

## Development and distribution notes

- The archived converter code retains the PC-port MIT LICENSE and NOTICE.
  Bundled decomp metadata has a separate provenance and must be reviewed
  before any public redistribution.
- `.dat` content is compiled from the user's ROM and is **not** provided with
  this source release.
- The active Phase 2 `main.cpp` opens the single `D:\data\007xb_assets.dat`.
  An older legacy intro loader with loose-file paths still exists in archived
  source, but is not called by the current gameplay entry point.
- The archive retains PC reference sidecars as in v0.5; this packaging pass
  makes **no modifications to runtime code, RNG, renderer, or game logic**.
